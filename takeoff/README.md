# CMM take-off aids (non-canonical)

This folder helps take-off software and people measure to CMM Edition 1.0. It is
**not part of the CMM release**. The release in `release/` controls: where anything
here differs from an item's own wording, follow the item. Nothing here restates CMM
measurement rules; items already state their unit, measurement basis and deductions.

| File | What it is | How it is made |
|---|---|---|
| `CMM-1.0-exclusion-refs.json` | For each of the 813 items, the items and sections its exclusion wording sends related work to, each with the sentence it came from. | Generated by `scripts/takeoff/build_refs.py`. Do not edit. |
| `coverage-guidance.json` | A small set of conditional prompts for related work, each quoting the CMM wording it relies on or marked as a gap, with evidence from a reference take-off. | Written by hand. Add an entry only when a reference take-off shows the need. |
| `quantity-policy.json` | Precision and billing rules. | Written by hand. |
| `reference/` | Hand-measured reference take-offs that automated take-off must reproduce. | Written by hand. |
| `DATA-SHAPE.md` | The proposed shape for ContechCost staged quantities, workings, location and coverage decisions. | For agreement before app changes. |

## Exclusion references are prompts, not requirements

A reference says where related work is measured *if it exists*. Spoil disposal depends on
where the spoil goes; a lintel can be masonry, timber or steel; some references are
boundaries ("windows within a curtain wall, measured at 17.A.2"). So the checker reports
plain references as advisory and enforces only what `coverage-guidance.json` states:

- `companion_if`: when the trigger item is measured, measure each listed item or record why
  it is not required.
- `one_of`: measure one of the alternatives, or record under the guidance id why none is required.
- `counting` and `measuring`: advisory notes, shown by their evidence.

Gaps (where CMM 1.0 is silent) are candidates for a later CMM edition once tests confirm them.
No CMM 1.1 change is proposed yet.

## Quantity policy

CMM Edition 1.0 states no rounding rule. `quantity-policy.json` records ContechCost house policy:

- Source measurements keep the precision the source supplied; nothing is rounded when staging.
- Squared totals are exact.
- Billed quantities are rounded for BOQ presentation or billing only. By default that is the
  nearest whole unit, half up, with any positive quantity under one unit billed as 1. Counts
  and lump sums must already be whole and are never rounded. Tonnes go to two decimal
  places. An item can carry its own override.

## Reference take-offs

Each one is measured to dimension-paper conventions: titles, trade headings, signposting,
waste calcs in mm, fraction timesing with dotting on, deduction rows, anding, and squared and
billed totals.

- `GS-01-garden-studio.json`: strip footing, slab on ground, and block wall with openings.
  14 entries.
- `CW-01-corner-window.json`: a coupled corner window, anonymised from a real job with changed
  dimensions. One assembly is counted once. The head and sill runs go along both faces from
  the opening sizes, not the frame sizes. The opening is deducted on both elevations but
  formed once.

## Checks

```bash
python3 scripts/takeoff/check.py        # add -v to list advisory exclusion refs
python3 -m unittest discover -s tests
```

`check.py` fails when:

- the exclusion references are stale;
- a guidance quote is not in the cited item's wording, or its evidence does not exist;
- a total does not square exactly from its rows;
- a row has the wrong number of dimensions for its CMM unit (a metre item takes one
  dimension; other sizes go in the description, per general rule 02);
- a dimension does not match the waste calc it cites;
- an item parameter is not stated;
- a billed figure breaks the quantity policy; or
- a guidance prompt is neither measured nor explained.
